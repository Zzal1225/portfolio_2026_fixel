## 첫 작업: step1 시작 전 준비 (코드 전에 이것만)
1. 기획서 "화면 2. 트랙 월드" 기준으로 배치 데이터(features/track/layout.ts) 타입을 제안해. 월드 640×360 안의 트랙 경로(타원을 몇 개 점으로 근사할지와 그 이유), 구조물 6개의 t·반응 구역 반경·스프라이트 위치, 인트로 때 전광판 글자가 바뀌는 경력 3줄의 t, 소품 좌표 목록이 들어가야 한다. Track World v3의 구조물 좌표와 소품 배치를 그대로 옮기되, 좌표는 코드로 베끼지 말고 데이터로 적어. "소품은 구조물 반경 2칸 밖"을 검사하는 단위 테스트도 같이 설계해.
2. 달리기와 카메라의 상태 흐름(idle → running → arrived, 네 방향 키 → 접선 내적으로 ccw/cw 결정(CLAUDE.md keyToDirection), 창 열림 중 입력 무시, 메뉴·미니맵 자동 이동은 최단 방향 + 2배 속도 + 캐릭터 가운데 고정, 평소 카메라는 여유 구간 40% + 월드 경계 클램프)과 인트로 흐름(신호등 → 절반 배율 한 바퀴 + 전광판 연도 → 줌인 → 인사 → 키캡 안내, SKIP·재방문·reduced-motion 분기)을 표나 그림으로 정리해. 내가 useRunner.ts를 짤 때 참고할 것이다.
3. step1 작업 목록을 기획서 "기능 범위" step1 행을 기준으로 작은 단위(각 1~2시간)로 쪼개서 제안해. 각 항목에 "끝났을 때 보이는 것"을 붙여. 첫 항목은 "임시 색 블록 월드 + 캐릭터 네모가 방향키로 트랙을 따라 돌고 카메라가 따라감"이어야 한다.
4. 내가 직접 짤 파일 2개에 대해 각각: 입력·출력, 쓰일 곳, 참고할 패턴, 흔한 함정(예: t가 1을 넘어 0으로 감길 때, 최단 방향이 정반대(0.5 차이)일 때, 커브 한가운데서 ↑와 ←를 같이 누를 때, 틱과 CSS transition 시간이 안 맞을 때, 카메라가 월드 경계에서 떨릴 때, 키를 누른 채 창이 열릴 때)을 설명해 줘. 본문 코드는 쓰지 마.
