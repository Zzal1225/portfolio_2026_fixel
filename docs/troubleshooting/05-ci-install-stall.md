# 5. CI가 10분 넘게 멈춤

## 문제
GitHub Actions CI는 평소 4분 걸리는데, 가끔 10분이 넘어도 끝나지 않았다(11-10 하루에 다섯 번).
멈춘 곳은 테스트가 아니라 `npx playwright install --with-deps`였다. 이 명령은 브라우저와 리눅스 의존 패키지 185개를 설치한다.

## 원인
apt가 Azure 미러에서 패키지 하나를 받다가 응답 없이 멈췄다. 로그에서는 `Ign:33 ... libtheoraenc2` 뒤로 진행이 없었다.
코드와 무관한 외부 요인이다.

## 시도한 것과 실패한 이유
1. **단계에 6분 제한**: 멈추면 실패로 끝날 뿐이라 사람이 다시 돌려야 했다.
2. **시도마다 3분 제한 + 3번 재시도**: 재시도가 전부 즉시 실패했다(`Could not get lock /var/lib/dpkg/lock-frontend`).
   `timeout`은 npx만 끊고, 그 아래에서 sudo로 돈 apt-get은 살아남아 잠금을 쥐고 있었다.
3. **apt 시간 제한·재시도 설정 + 재시도 전 apt 프로세스·잠금 정리**: 통과는 했다. 하지만 세 번째 시도에서야 성공해 15분이 걸렸다.

## 해결
설치를 고치지 않고 **설치 자체를 없앴다**. CI의 E2E 잡과 스냅샷 잡을 브라우저·의존 패키지가 미리 들어 있는
Playwright 공식 이미지(`mcr.microsoft.com/playwright:v1.65.0-noble`)에서 돌린다(`.github/workflows/ci.yml` `container`).
이미지 태그는 `@playwright/test` 버전과 맞춰 함께 올린다.
화면 비교 기준 스크린샷도 같은 이미지에서 찍는다. 다시 찍어 보니 기존 기준과 픽셀 단위로 같았다.
스냅샷 커밋은 git이 확실히 있는 러너 잡으로 분리했다.

함께 줄인 것: CI의 Lighthouse를 3회 → 1회로 줄였다(경고용). 정식 기록은 로컬에서 3회 중앙값으로 남긴다.

## 결과
| | 전 | 후 |
|---|---|---|
| CI 전체 | 약 10분, 가끔 15분 이상 또는 멈춤 | **3분 28초**(E2E 37개 + Lighthouse) |
| 설치 단계 | 1~10분 이상, 불안정 | 없음(이미지 받기 수십 초) |

배운 것: 외부 불안정을 재시도로 다룰 때는 프로세스 트리 전체를 정리해야 한다. 그보다 나은 답은 불안정한 단계를 아예 없애는 것이다.
