# 박찬령 포트폴리오 사이트 기획서 (트랙 컨셉)

2026-11-09 확정, 11-09 저녁 월드 2배·영어 메뉴 6개 개정, 같은 날 인트로(전광판 연도·줌아웃·인사·키캡) 개정, 12시 Design 결과 반영(네 방향 키·인사 영어·연도 3줄·전광판 3×1·REPLAY·모바일 MAP 창·정수 줌), 11-10 시안 변경 반영(전광판 자기소개 문구 4개·평소 "CAREER"·인필드 이정표) · 박찬령 (작업 폴더 `portfolio-pixel`, 원본: Claude Doc https://claude.ai/artifact/8Ns3gHHQexV8FNSuLtLViq)

## 서비스 소개

도트(픽셀아트) 게임 컨셉의 1인 포트폴리오 사이트입니다. 화면보다 큰 **400m 육상 트랙 월드(탑뷰)** 위를 캐릭터가 달리고 카메라가 따라갑니다. 트랙 위 구조물 6개(START · FINISH 아치, 전광판, 급수대 2, 천막, 접수 테이블) 앞에 서거나, 화면 가장자리 메뉴 아이콘이나 미니맵을 누르면 ABOUT · CAREER · PROJECT 1 · PROJECT 2 · EDUCATION · RESUME 창이 열립니다. 첫 방문에는 출발 신호등이 켜지고 캐릭터가 트랙을 한 바퀴 도는 약 7초짜리 인트로가 재생됩니다. 기존 사이트(https://portfolio2026-tau-plum.vercel.app)를 대체하며 처음부터 새로 만듭니다. 사이트 이름은 따로 짓지 않고 "박찬령 포트폴리오"입니다.

**왜 트랙인가**

- 러닝은 실제 취미이고 대회 참가 경험이 있어, 면접에서 "왜 트랙이에요?"에 설명 없이 답이 됩니다. 남의 배경이 아니라 본인 이야기입니다.
- 트랙 한 바퀴가 곧 경력 코스입니다. 2013 의류매장 → 2018 공인중개사 → 2023 퍼블리셔 과정 → 2023~2026 파워텔레콤 → 지금. "다른 길에서 프론트엔드로 왔다"는 이야기는 전광판(= CAREER 메뉴) 창의 코스 그림이 맡고, 인트로 한 바퀴 동안 전광판에는 "DISCOVER → PLAN → BUILD"와 자기소개 문구 4개가 찍힙니다(11-10 결정).
- 주제어는 **"기록"**입니다. 마라톤 기록, nanaki(기록 앱), dahda(보낸 문자가 닿았는지 = 완주 확인), Lighthouse 수치(성능 기록). 사이트 전체가 "기록을 재고 끝까지 닿게 하는 사람"으로 묶입니다.
- 러닝 요소는 **트랙·아치·번호표까지만** 씁니다. 창 안의 내용은 철저히 개발 이야기입니다. 러닝은 무대이고 내용은 코드입니다.

## 화면 구성

### 화면 1. 인트로 (첫 방문만, 약 7초 + 인사) — 11-09 저녁 개정

인트로 동안은 **배율을 반으로 내려 월드 전체를 보여 줍니다**(PC 4×→2×: 월드 640×360이 1280×720에 통째로 들어옴. 태블릿 3×→1.5×는 쓰지 않고 2×로 통일, 모바일 2×→1×). 그래서 한 바퀴 내내 인필드 전광판이 보입니다. 한 바퀴가 끝나면 출발선의 캐릭터로 줌인하며 평소 배율로 돌아옵니다.

1. **출발 신호등**(1.5초): 아치 옆 신호등이 빨강 → 노랑 → 초록으로 0.5초 간격으로 켜지고, 화면 가운데 픽셀 글자 "ON YOUR MARKS" → "SET" → "GO". 초록과 함께 심판 캐릭터가 깃발을 내립니다. 소리는 없습니다(효과음 자체를 넣지 않음).
2. **한 바퀴 + 전광판 문구**(5초): 캐릭터가 아치 아래 분필 출발선에서 시계 반대 방향으로 한 바퀴 달립니다. 전광판 위쪽 띠에 **"DISCOVER → PLAN → BUILD"**(Press Start 2P), 아래에 캐릭터 위치(t)에 맞춰 **자기소개 문구(HTML, Galmuri)**가 바뀝니다: t 0.05 "문제를 찾고," → 0.3 "해결 방법을 기획하고," → 0.55 "실제 결과물로 만드는" → 0.8 "프론트엔드 개발자 박찬령입니다." 문구 1·2·3일 때 띠의 해당 단어만 노랑으로 켜지고 문구 4에서 셋 다 켜집니다. 아래 가운데 진행 점 4개가 하나씩 켜집니다(11-10 시안 채택. 경력 연도는 CAREER 창으로). 경기장 전광판에 기록이 찍히는 연출이며, 레인 옆 말풍선은 없습니다. 화면은 흑백에서 시작해 달릴수록 컬러가 됩니다(CSS `filter: grayscale()` 보간). 마지막 줄부터 완전한 컬러. 전광판이 화면 밖인 경우(모바일 세로 1×)에는 같은 글자를 화면 위쪽 띠(전광판과 같은 검은 바탕)로 대신 보여 줍니다.
3. **줌인**(0.4초): 출발선에 멈춘 캐릭터를 가운데 두고 2× → 3× → 4× **정수 단계로 두 번에** 확대합니다(각 0.2초, 소수 배율을 거치지 않음. Design 스토리보드 방식 채택). 이 순간이 "영상 → 게임"의 전환이고, HUD·미니맵이 함께 나타납니다. 전광판 글자는 평소 표시 "CAREER"로 돌아갑니다.
4. **인사**(2.5초): 캐릭터가 정면(아래 보기)으로 서서 손을 흔들고(2프레임), 머리 위 말풍선(Press Start 2P) **"WELCOME TO MY PORTFOLIO!"**(영어, 메뉴·HUD와 통일. 11-09 결정). 이때부터 조작이 가능하며, 입력이 들어오면 말풍선은 바로 사라집니다.
5. **조작 안내**: 인사 말풍선이 사라지면 캐릭터 양옆에 픽셀 **키캡 ← →**가 번갈아 눌리는 애니메이션(2프레임)이 뜹니다(네 방향 키를 다 받지만 안내는 좌우 두 개로 충분). 첫 키 입력·터치·메뉴 클릭에 사라집니다. 모바일은 키캡 대신 ◀ ▶ 버튼이 깜빡입니다. 트랙 아래 안내 띠는 두지 않습니다(캐릭터 옆에 있어야 "이걸 움직인다"가 읽힘).
6. **REPLAY**: 인트로가 끝나면 왼쪽 아래에 작은 "▶ REPLAY" 버튼이 남아 인트로를 다시 볼 수 있습니다(SKIP한 담당자용. Design 시안 채택). 누르면 열린 창을 닫고 1번부터 다시.

- 오른쪽 위 "SKIP" 처음부터 표시. 아무 키·탭·클릭도 건너뛰기(인사 단계로 바로 감).
- 재생 중 스프라이트·폰트·창 내용을 미리 불러오고, 다 받지 못했으면 출발선 앞에서만 짧게 대기(여기서만 로딩 표시).
- 두 번째 방문부터는 신호등·한 바퀴 없이 평소 배율에서 **짧은 인사(1.5초) → 키캡 안내**만. `prefers-reduced-motion`이면 한 바퀴·줌·손 흔들기 생략, 인사 말풍선은 고정 표시.
- 퇴사·재입사(2025.09~12)는 인트로에 표시하지 않고 CAREER 창에서 한 줄로 설명.
- 시안은 Design 6컷 스토리보드(Intro Storyboard.dc.html)로 확정됐고, 움직임은 코드로 만듭니다(step1 1차, step2 완성).

### 화면 2. 트랙 월드 (첫 화면)

- **월드는 화면보다 큽니다.** 내부 해상도 640×360(20×11.25칸), 타원 트랙이 월드를 꽉 채웁니다. PC(1280 폭)에서 4배로 띄우면 월드가 2560×1440이라 한 화면에 트랙의 약 1/4이 보이고, **카메라가 캐릭터를 따라갑니다**(가운데 여유 구간 안에서는 안 움직이고, 월드 가장자리에서 멈춤). 배율은 **정수**(모바일 2×, 태블릿 3×, PC 4×), `image-rendering: pixelated`.
- **모바일**: 같은 월드를 2배로 띄우고 카메라가 보여 줍니다. 세로 전용 배치가 따로 없고, 가로 방향도 강제하지 않습니다. 가로로 돌리면 보이는 범위만 넓어집니다.
- **미니맵(PC)**: 오른쪽 아래 160×90. 타원 윤곽 + 구조물 점 6개 + 캐릭터 점 + 현재 화면 네모. 점을 누르면 그 지점으로 달려갑니다(메뉴와 같은 역할). HTML/SVG로 그려 배율과 무관하게 선명. **모바일은 미니맵 대신 오른쪽 위 "MAP" 버튼**으로 전체 지도 창(Dialog)을 열고, 지도 위 구조물을 누르면 달려갑니다(작은 화면에서 미니맵 점은 누르기 어려움. Design 시안 채택).
- 캐릭터는 트랙 레인 위에만 있습니다(레일 위를 달리듯). 위치는 트랙 한 바퀴를 0~1로 나타낸 값 `t` 하나이고, 진행 방향은 시계·시계 반대 둘뿐입니다. **입력은 네 방향 키를 모두 받습니다**: 누른 키의 방향과 현재 지점의 트랙 진행 방향(접선)을 비교해 가까운 쪽으로 달립니다(위쪽 직선에서 ←는 반시계, 오른쪽 커브에서 ↑는 반시계. 11-09 B안 확정). 수직인 키(직선 구간에서 ↑↓)는 무시. 서 있을 때 idle 애니메이션(숨 쉬기 2프레임). 한 바퀴 약 12초(월드가 커졌으므로 속도도 2배 가까이 올림), 자동 이동은 2배.
- 월드가 커진 만큼 **소품**으로 채웁니다(아래 "소품 규칙").

- 눈에 띄는 순서는 트랙 → 캐릭터 → 아치 → 구조물 → 소품.

**소품 규칙 (허전함 대책)**

- 소품은 캐릭터보다 작은 **1×1칸**, 팔레트 16색 안, 팝업 없음, `aria-hidden`.
- 트랙: 레인 번호 분필, 출발 블록, 콘, 가장자리 배수로 선, 100m 지점 분필 표시.
- 관중석: 트랙을 둘러싸는 띠로 확장, 관중은 2~3색 점, 깃발 줄(bunting) 한두 줄.
- 잔디: 민무늬 기본 + 색이 살짝 다른 큰 패치, 벤치·물통·가방·수건, 긴 그림자.
- 인필드: 전광판 + **이정표**(왼쪽 아래, 48×50, 화살표 판 3장에 HTML 글자 "경험은 넓게 / 실행은 빠르게 / 성장은 꾸준히", 창 없음, 11-10 시안 채택). 소품은 이정표와도 겹치지 않습니다.
- **구조물 반경 2칸 안에는 소품을 두지 않습니다.** 어디가 "누르는 곳"인지 계속 분명해야 합니다.

**조작 4가지, 모두 같은 결과**

1. **키보드**: ↑↓←→ (WASD)를 모두 받고, 트랙 진행 방향에 가까운 쪽으로 달림(B안). 누르고 있으면 계속 달리고 떼면 멈춤. 반응 구역에 서면 머리 위 `!` 말풍선, Enter·Space로 창 열기, ESC로 닫기.
2. **터치**: 양쪽 아래 구석 **◀ ▶ 버튼 두 개**(누르고 있는 동안 달림). 화면에 보이는 구조물을 직접 탭하면 가까운 방향으로 달려가 도착 즉시 열림. 4방향 패드는 없습니다.
3. **메뉴 아이콘**(PC 상단, 모바일 하단): 캐릭터가 가까운 방향을 계산해 그 지점까지 2배 속도로 달려간 뒤 창이 열림. 멀면 카메라가 빠르게 따라감.
4. **미니맵 점(PC) / MAP 창의 구조물(모바일)**: 메뉴 아이콘과 같음.

- HUD(DOM): 왼쪽 위 **번호표 모양 이름 띠** "박찬령 · LV.3 FRONTEND"(캐릭터 가슴 번호표는 너무 작아 글자 없이 빈 판), 메뉴 아이콘 6개(PC 오른쪽 위 가로 한 줄 / 모바일 하단 ◀ ▶ 사이), 오른쪽 아래 미니맵(모바일은 오른쪽 위 MAP 버튼), 왼쪽 아래 ▶ REPLAY. 조작 안내는 트랙 아래 띠가 아니라 캐릭터 양옆 키캡 ← → 애니메이션(화면 1의 5번, 첫 입력까지).
- 다크 모드 없음(낮 경기장 한 가지).

### 화면 3. 창 (Dialog)

- Radix Dialog. PC는 가운데 720px 폭, 모바일은 아래에서 올라오는 전체 높이 시트. 픽셀 테두리(9-slice) 안쪽은 보통 HTML(제목 Press Start 2P, 본문 Pretendard).
- 창이 열려 있는 동안 달리기 입력은 멈춤. 닫으면 캐릭터는 그 자리에.
- 창 상단에 이전·다음 구조물 화살표(트랙 순서대로 넘기기). 순서 강제가 아니라 편의입니다.

## 기술 스택

게임 엔진(Phaser·PixiJS)과 캔버스는 쓰지 않습니다. 글·버튼이 DOM이라 접근성이 그대로 유지되고, 번들이 가볍고, 면접에서 직접 설명할 수 있는 코드가 되기 때문입니다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js (App Router) + TypeScript (strict) | nanaki·dahda와 동일, OG 메타·정적 생성 |
| 게임 렌더링 | DOM + CSS. 월드 컨테이너 하나를 `transform: translate3d`로 움직여 카메라를 만들고, 스프라이트는 시트 `background-position` + `steps()` | 글·버튼이 DOM이라 접근성 그대로. 엔진 없음 |
| 게임 상태 | Zustand (`t`·방향·달리는 중 여부·목표 지점·카메라 위치·열린 창·인트로 상태) | 입력 처리와 렌더 분리 |
| 트랙 경로 | 직접 구현 `trackPath.ts`: `t`(0~1) → 월드 픽셀 좌표·바라보는 방향, 두 지점 사이 최단 방향 | 단위 테스트 대상. 사용자 직접 작성 |
| 이동·카메라 | `useRunner.ts`: 키·터치·메뉴 입력을 상태 머신(idle → running → arrived)으로, 카메라는 캐릭터 좌표에서 여유 구간·경계 계산 | 고정 틱 + CSS transition. 사용자 직접 작성 |
| 미니맵·MAP 창 | PC: 인라인 SVG. 타원 path + 점 6개 + 현재 화면 rect. 점은 `<button>`. 모바일: 같은 SVG를 Dialog 안에 크게 | 배율과 무관, 접근성 |
| 창 | Radix Dialog + Framer Motion | 포커스 트랩·ESC·스크롤 잠금 기본 제공 |
| 스타일 | Tailwind + 디자인 토큰(nanaki 토큰 JSON 규칙, 라이트 값만) | |
| 폰트 | Press Start 2P(OFL) 영어 라벨·HUD·창 제목, 갈무리(OFL) 한국어 픽셀 글자(연도 말풍선), Pretendard 본문 | 라벨이 영어라 영어 픽셀 폰트가 더 또렷 |
| 테스트 | Vitest(경로 변환·최단 방향·반응 구역·카메라 경계·상태 머신·인트로 조건), Testing Library, Playwright(+axe, 화면 비교 PC 1280·모바일 390) | |
| CI/CD | GitHub Actions, Lighthouse CI, Vercel | |

- 이동은 연속값 `t`를 고정 틱(예: 60ms)마다 갱신하고 CSS transition으로 보간합니다. 카메라도 같은 틱에서 목표를 계산하고 transition으로 따라갑니다. `requestAnimationFrame` 루프는 쓰지 않습니다. 프레임 저하가 측정되면 step2에서 월드 배경(트랙·잔디·관중석·소품)만 `<canvas>` 한 장으로 합치는 것을 검토합니다.
- 픽셀 그림은 `public/sprites/`에 시트 PNG로. 시트당 16색 이내. 월드 배경은 타일 32×32를 CSS로 반복해 그리므로 큰 PNG 한 장이 필요 없습니다.

## 면접 예상 질문

- 왜 트랙인가, 취미 사이트로 보이지 않게 어떻게 선을 그었나
- 왜 Phaser 같은 게임 엔진을 쓰지 않았나 (접근성·번들·"내가 설명할 수 있는 코드")
- 트랙 위 이동과 카메라를 어떻게 구현했나 (`t` 하나로 위치·방향, 최단 방향 계산, 상태 머신, 월드 컨테이너 transform, CSS transition)
- 월드를 화면보다 크게 한 이유와 2배로 제한한 이유 (걷는 의미 vs 한 바퀴 12초)
- 인트로가 채용 담당자에게 방해되지 않나 (7초·SKIP·첫 방문만·reduced-motion·메뉴로 바로 열기·인사부터 조작 가능)
- 인트로에서 배율을 바꾼 이유 (월드 2배인데 전광판 문구를 보여 주려면 전체가 보여야 함, 정수 배율 2×↔4×)
